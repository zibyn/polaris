# 安全与合规

所有计数器和临时状态都存在 PG 中。

## 发送限流

| 维度 | 阈值 |
|---|---|
| 单个手机号或邮箱 | 60 秒 1 次;每小时 5 次;每天 10 次 |
| 单个 IP | 每小时 20 次 |
| 全实例每日发送上限 | 默认 1000 条,管理员可以调整;达到上限后停发,并在管理端提示 |

除每日上限外,其他阈值都是固定值。

**关闭开放注册时**(ADR 0021),验证码登录先查目标手机号或邮箱是否属于某个 User,不属于就直接拒绝:不发验证码,也不计入上面任何一条限流。全实例每日上限被随机号码刷光时,关闭注册就是止血手段。代价是拒绝提示会暴露某个手机号或邮箱是否已注册;这是管理员主动选的,可以接受。

**注册邀请**算一次发送,只计入全实例每日上限,不计入按手机号 / 邮箱 / IP 的那三条:邀请邮件里没有验证码,而发它的是已认证的管理员,不是等着收码的陌生人。

## 防机器刷

内置工作量证明(ALTCHA 协议,MIT 许可的 Go 库)。"发送验证码"和"密码登录"请求都必须附带解答;托管页面在浏览器里计算,原生 App 由 KMP SDK 计算。不对接商业行为验证码。托管页的「重新获取」是唯一的例外:它只重发到本次登录已经发过码的那个标识,不能换目标,按标识符的发送限制照常生效。

## 失败锁定

- **密码**:同一账号连续输错 5 次,锁定**密码登录** 15 分钟。验证码和 Passkey 登录不受影响。
- **TOTP**:每个待完成的登录最多输错 5 次(TOTP 和恢复码合计),第 5 次后本次登录作废。不按 User 锁定。
- **单个 IP**:每小时累计 50 次失败,之后拒绝其登录请求 1 小时。错误的密码、验证码、TOTP 和恢复码都计入。

## 防重放

- **TOTP**:某个时间步的码被接受后,不早于这个时间步的码一律拒绝,同一个码不能用第二次。
- **恢复码**:每个只能用一次。

## 审计日志

- **记录**:
  - Management API 的全部写操作,含 M2M Application 以自身身份做的(ADR 0015):操作人带类型,记为该 Application 的 client_id,而不是被误当成某个 User;
  - User 安全事件:绑定或解绑、开关两步验证、重新生成恢复码、用掉恢复码(`recovery_code.used`)、增删改 Passkey(`passkey.added` / `passkey.removed` / `passkey.renamed`)、Passkey 计数器回退被拒(`passkey.counter_regressed`)、改密码、下线 Session、注销;
  - User 生命周期:管理员创建(`user.created`)、发出与撤销注册邀请(`invite.sent` / `invite.revoked`,操作人是管理员)、本人接受邀请(`invite.accepted`,操作人是本人)、待激活的本人改密激活;
  - 登录成功(`login.succeeded`):User 每完成一次身份证明记一条,含同一浏览器里的重新登录;开了两步验证的,第二步通过后才记。带 `client_id`、`amr`、IP、UA。账号中心的重新认证也是一次身份证明,同样记,`client_id` 为 `polaris-account`。Session 会被删除,也只留最近一次的 IP 和 UA,替代不了这条记录;
  - 登录失败(`login.failed`):只记能对应到某个 User 的,即密码错误(含对已锁定的 User 试密码)、验证码错误、TOTP 错误、恢复码错误。账号中心重新认证输错同样记。带方式、`client_id`、IP、UA。对应不到 User 的失败由单个 IP 的锁定兜住,不逐条记;
  - 登录锁定;
  - 触发每日发送上限。
- **不记录**:refresh token 换新令牌、浏览器已有 Session 时静默进入另一个 Application;`client_credentials` 换令牌(每 10 分钟一次,会淹没其他事件)。
- **保留与导出**:默认保留 180 天,可以调整;管理端可以筛选,二期支持导出 CSV。

## 协议同意

- **文本**:管理员在后台填写《用户协议》和《隐私政策》的 URL 与版本号,全实例一份。Polaris 不托管文本。
- **托管登录页**:"我已阅读并同意"复选框默认不勾选,不勾不能登录。
- **直连 API**:请求必须带上所同意的版本号,界面由 App 自己画;当前的 URL 与版本号由公开的 `GET /v1/auth/terms` 提供。
- **记录**:每次同意都记录 `sub`、版本、时间、经由的 Application。
- **改版**:版本号更新后,User 下次登录须重新同意。

## 实名

只有"必须绑定手机号"开关。法规的触发条件是信息发布、即时通讯类服务,由运营方按自己的 Application 判断是否打开。

## 数据留存

| 数据 | 留存 |
|---|---|
| 验证码、PoW 题目、限流计数、临时登录状态 | 过期后由每小时一次的清理任务删除 |
| 已过期或被替换的注册邀请 | 同上(表里只有 token 的哈希) |
| 已终止或已过期的 Session(含最近的 IP 和 User-Agent) | 30 天 |
| 审计日志 | 180 天,可以调整;注销后只保留 `sub`,事件里的 IP 和 UA 随之清除 |
| 同意记录 | 随 User 注销一起删除 |
| 已注销的 User | 不保留任何数据 |

## 个人信息导出

账号中心提供"导出我的数据"。重新认证后,当场生成一个 JSON 文件,内容包括:
- Identifier;
- External Identity(只含服务商名称和绑定时间);
- Credential 元数据(不含任何密钥);
- Session(含最近的 IP 和 UA);
- 同意记录;
- 与本人相关的审计事件。

## 由运营方负责

未成年人保护、数据出境、等保测评、运营商二次放号风险,在部署文档中逐项提醒。
