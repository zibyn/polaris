# 管理端与账号中心

两者都内嵌在二进制中,技术栈为 TanStack + shadcn/ui(Base UI 原语)。管理端是内置的 First-party Application,经 OIDC 登录,数据全部来自 Management API。管理端和账号中心只做中文界面,不引入 i18n 框架(托管页的中英双语见[登录页](#登录页));界面上每个概念叫什么,以下文的[界面用语对照表](#界面用语对照表)为准。

## 管理端

### 读者

- **应用、API 资源、认证源、设置**四组面向开发者:可以保留 `client_id`、回调地址等必要术语,每个都配一句人话说明。
- **用户、审计**两组面向运营和客服:不出现协议词汇。

### 导航

侧栏是「概览」加三个带标题的分区,每项配一个 lucide 图标,依次为:

| 分区 | 项 | 页面与层级 | 所需 Permission |
|---|---|---|---|
| — | **概览** | 上手清单、统计与趋势、最近事件、快捷操作、配置状态(见[概览](#概览))。 | `users:read` |
| 身份认证 | **应用** | 列表 → 应用详情页。 | `applications:read` |
| | **API 资源** | 列表 → API 资源详情页。 | `applications:read` |
| | **登录体验** | 单页三个 Tab:登录方式、品牌、用户协议,右侧实时预览登录页(见[登录体验](#登录体验))。 | `config:read` |
| | **认证源** | 列表 → 选类型 → 编辑页(即详情页)。 | `config:read` |
| | **验证码通道** | 短信、邮件、每日发送上限(见[验证码通道](#验证码通道))。 | `config:read` |
| 用户管理 | **用户** | 列表 → 用户详情页。 | `users:read` |
| | **角色与权限** | 所有 API 资源上的角色汇总(见[角色与权限](#角色与权限))。 | `users:read` |
| 系统 | **审计日志** | 单页列表加筛选,不设事件详情页。 | `audit:read` |
| | **安全** | 令牌签名密钥、审计保留期。 | `config:read` |

- 分区里一项都看不到时,分区标题也不显示。列表项右侧可带灰色计数(应用、API 资源、认证源、用户),数据来自已经加载的列表或概览,不为计数单独请求。
- **顶栏**:面包屑在左;右侧依次为全局搜索框(「搜索用户、应用、API 资源…」加 `⌘K` 提示)、文档链接。窄屏时侧栏收成抽屉,顶栏左侧放菜单按钮。
- **全局搜索**(`⌘K` / `Ctrl+K` 或点搜索框):对话框内一个输入框,结果按「页面 / 用户 / 应用 / API 资源 / 认证源」分组,上下键选择,回车跳转。页面和应用、API 资源、认证源在前端按名称和标识过滤;用户走 `GET /users?q=`,输入停 200ms 再查,最多 5 条,末尾给「在用户列表中查看全部」。只搜读者有权限的对象。
- 旧地址 `/console/settings?tab=…` 重定向到新位置(`login` / `terms` / `brand` → 登录体验对应 Tab,`channels` → 验证码通道,`security` → 安全)。

- **详情一律是独立页**,可以链接;**列表页不直接内嵌创建、添加、编辑表单**:一律用右侧抽屉(短表单、确认类输入用对话框),列表或详情页留在背后不跳走。多步创建(创建应用先选平台、添加认证源先选类型)也在抽屉里分步完成,列表 URL 带 `?create` / `?add` 打开抽屉。
- **按钮可见性**:缺少相应 Permission 的操作按钮不显示。
- **密钥字段**:只写不回显,只显示"已设置 · 更新于 X",只能整体替换。
- **Tab**:页面里的 Tab 一律用 shadcn Tabs(`variant="line"`,不另加样式),当前 Tab 放在 `?tab=`,不带参数即默认 Tab。
- **保存**:表单按卡片保存,保存栏在卡片底部(「撤销修改」+「保存」);前端把同一资源里没改的值原样带回,Management API 不变。只有一个开关的设置拨动即保存(见[登录体验](#登录体验)),不配保存按钮。

### 页面

#### 概览

- 从上到下:上手清单(未完成时)、统计、左侧最近事件 + 右侧快捷操作与配置状态。
- **统计**:四张统计卡:用户、今日新登录(悬浮说明"今天新建的会话数")、活跃会话、应用(只计非内置,前端按 `builtin` 过滤)。用户和今日新登录下方各有一条近 7 天的趋势线(新增用户数、每日新建会话数),数据来自 `GET /overview` 的 `trend`(需新增,按天聚合,最近 7 天);趋势线只是走势,不画坐标轴,悬浮显示当天数值。
- **最近事件**:与审计页用同一句话,每行前有事件类型图标,失败和锁定类用红色图标;右上「查看审计日志」。
- **快捷操作**:创建用户、创建应用、添加认证源、接入文档,按读者权限显示。
- **配置状态**:短信通道、邮件通道、Passkey 开关、令牌签名密钥上次轮换时间,各一行,右侧状态徽章;每行链到对应页面。它只陈述现状,不打分。
- **上手清单**:三步,依次为 配置通道 → 创建应用 → 添加 API 资源。完成状态由 `GET /channels` 和应用、API 资源列表的 `builtin` 推出;左侧是标题和进度条(已完成 N / 3),右侧三步并排,完成的打勾,未完成的给主按钮;看不到的步骤不显示;全部完成后自动隐藏,也可以手动关掉。它是一次性的上手引导,不做持续的配置健康检查。
- 每日发送上限的告警条保留不变。

#### 用户

- **列表**:搜索手机号、邮箱、用户名或用户 ID;状态分段控件(全部 / 已激活 / 待激活 / 已禁用);「角色」「认证源」两个筛选(虚线按钮,选中后变成可清除的标签);列为 用户(头像、主标识、姓名与其他标识)、状态、角色、最后登录;页头有「导入」和「创建用户」。最后登录来自 `GET /users` 每项的 `lastLoginAt`(需新增,取该用户最近一次 `login.succeeded`,从未登录写「从未登录」);认证源筛选需 `GET /users?provider=<id>`(需新增)。
- **导入**:抽屉里上传 CSV(列:`phone`、`email`、`username`、`name`、`passwordHash`,至少一个标识),先预览前 20 行和校验错误,确认后前端逐个调用 `POST /users`(ADR 0033,不设批量接口),显示进度;完成后列出失败行和原因,可下载失败行 CSV 改完重导。关掉抽屉即停止,已导入的保留。
- **创建用户**在用户列表的抽屉里(另有独立页 `/console/users/new` 可直接链接),两项:登录标识,与**激活方式**(「设初始密码」/「发注册邀请」,默认前者)。标识符可以是手机号、邮箱或用户名,选邀请时必须是邮箱——邀请只发邮箱。管理员填的邮箱或手机号**直接算已验证**,不发验证邮件、不消耗验证码条数。初始密码由管理员当面或另找渠道交给本人,本人第一次登录时必须改掉;邀请是一条 7 天有效的一次性链接,密码只经过本人。成功后进入新用户的详情页;邀请邮件发不出去时账号**已经建好**,页面上就说明这一点并让人去用户页重发——不然管理员会当它没建成再点一次,那次撞的是「这个邮箱已属于另一个 User」。密码登录关闭时入口禁用并说明原因(见[依赖提示](#依赖提示))。
- **待激活**的账号(管理员建出来、本人还没设置自己的密码)在列表和详情都标出来,状态筛选里与「已激活」相对;这个状态本身见 [identity.md](identity.md#待激活与激活)。
- **用户详情**头部之下分三个标签,`?tab=` 取值 `profile`(默认)/ `security` / `roles`:「资料」放个人资料、登录标识与密码、注册邀请;「登录与安全」放已绑定的外部账号、两步验证、Passkey、会话;「角色」单独一个标签。各分区如下:
  1. **头部**:主登录标识、状态(已激活 / 待激活 / 已禁用)、禁用 / 删除操作;标识条里是用户 ID 和注册时间。待激活的账号在状态下面加一句说明:本人设置自己的密码之前拿不到任何令牌。
  2. **登录标识与密码**:手机号、邮箱、用户名(可更换)与密码状态。
  3. **注册邀请**:未发出 / 已发出(写明什么时候过期)/ 已接受。持有 `users:write` 的管理员可以发出、重发、撤销(对方是管理员时还需要 `admin-roles:assign`,和禁用、删除管理员一致),都先弹确认框(正文写后果:重发让旧链接立刻失效,撤销后本人得找管理员重发)。发出的去向是账号上的邮箱;没有邮箱的账号不给按钮,只显示状态和一句说明。只读角色只看到状态。
  4. **已绑定的外部账号**:列出本用户绑定的认证源(解绑规则见[认证源](#认证源))。
  5. **两步验证**:已开启 / 由 Passkey 满足(没开两步验证但有 Passkey)/ 未开启。已开启时,持有 `users:write` 的管理员看到「重置两步验证」按钮(对方是管理员时还需要 `admin-roles:assign`,和禁用、删除管理员一致),先弹确认框(提醒先线下核实身份;清除验证器和全部恢复码,已登录的设备不下线)。只读角色只看到状态。
  6. **Passkey**:每把显示名称、创建时间和最后使用时间(尚未使用就写"尚未使用");没有 Passkey 时显示空状态。持有 `users:write` 的管理员可以删除某一把(对方是管理员时还需要 `admin-roles:assign`,和禁用、删除管理员一致),先弹确认框;删除写审计,操作人是管理员本人,和用户自己删除区分开。只读角色只看不能删。「重置两步验证」不动这里的任何一把。
  7. **会话**:可以下线,也可以一次下线全部会话。
  8. **角色**:按 API 资源分组,是**唯一**给 User 分配角色的地方。
- 详情页上有「查看审计记录」链接,跳到按该用户筛选的审计页。

#### 应用

- **创建**见[创建应用与接入清单](#创建应用与接入清单)。
- **应用详情**按关注点分标签,每个标签只有一个「保存」(参照登录体验的 Tab),`?tab=` 取值见括号;某类应用没有的标签不显示:
  - **基本**(`basic`):名称、类型(只读;「无后端应用 / 有后端应用 / 后端服务」,写明各适合什么、创建后不能改)、默认 API 资源(链到对应的 API 资源详情)、「要求用户有角色」开关(让 User 登录的应用;没选默认 API 资源时置灰并说明原因,见 [rbac.md](rbac.md#签发时检查-role)),一起保存;页面底部是红框删除区。后端服务的默认 API 资源只读:它换到的令牌只对这个 API 有效,创建后不能改。`client_id` 在头部标识条。
  - **凭据**(`credentials`,无后端应用没有):客户端认证方式,共享密钥 / 私钥签名单选,切换前确认;共享密钥下有 client secret 与重新生成,私钥签名下 secret 作废;Application 公钥以 JWKS 文本框登记,与认证方式分开保存(ADR 0023)。
  - **登录**(`login`,后端服务没有,它不登入任何 User):回调地址;「高级」折叠区里放退出后跳转地址、首页地址(账号中心「返回」链接的去处,https,本机可用 http;ADR 0034)、「闲置多久需重新登录」、「允许 App 保持登录」。
  - **登录方式**(`methods`,后端服务和内置应用没有,内置应用永远跟随实例):默认跟随实例;打开「只允许指定的登录方式」后勾选短信验证码、邮箱验证码、密码、Passkey 和各个认证源(停用的标「已停用」),至少勾一个,保存后只影响之后的登录(见 [authentication.md](authentication.md#按-application-指定登录方式))。
  - **品牌**(`brand`,后端服务和内置应用没有):品牌名、Logo、主色,和登录体验的品牌 Tab 同一套控件;默认跟随实例,填了哪项只换哪项,留空的继续跟随。
  - **原生 App**(`native`,只有无后端应用):iOS 的 Team ID + Bundle ID、Android 的包名 + SHA-256 签名指纹,各按行登记在文本框里,可以增删;保存后认证服务据此生成 `/.well-known/` 关联文件(见 [authentication.md](authentication.md#密码管理器适配)),iOS 和 Android 就允许这些 App 使用这个域名的通行密钥和密码自动填充。
  - **角色**(`roles`,只有后端服务):勾选它在其默认 API 资源上持有的 Role,它换到的 access token 带上这些角色与权限(见 [rbac.md](rbac.md))。默认 API 资源是管理 API 时,需要 `admin-roles:assign`;该 API 资源还没有角色时,链到 API 资源详情去建。
  - **通知**(`webhook`):有后端应用的退出通知地址(Back-Channel Logout,`backchannel_logout_uri`,见 [protocol.md](protocol.md#back-channel-logout)),和所有应用的用户删除通知地址与 Webhook 密钥,一起保存;地址留空即不发。
  - **没有可用的登录方式**:指定的方式在实例里都没开(或指定的认证源被删除)时,应用详情头部显示警告「这个应用指定的登录方式在实例里都没开,现在没有人能登录它」,链到登录方式标签。实例关掉某种方式时不拦截,只靠这条警告。
- 样页(应用详情的全部改写文案)见原型 [`prototype/console-copy`](https://github.com/zibyn/polaris/blob/prototype/console-copy/prototypes/console-copy/index.html) 的 A 版,以其 `NEW` 对象为准;删除区用 C 版的红框独立区块。

#### API 资源

- **API 资源详情**有「权限」「角色」两个标签。
- 添加 API 资源、添加权限、添加 / 编辑角色都用右侧抽屉,列表与详情留在背后。
- 角色行显示持有人数(含持有它的 M2M Application);点击跳到按该角色筛选的用户列表。
- 业务 API 资源的角色行有「默认」勾选,勾上后新 User 创建时自动获得该 Role(见 [rbac.md](rbac.md));只读角色看到的是「默认」徽章。内置 API 资源上不出现。
- 显示"被哪些应用用作默认 API 资源",并链到这些应用。
- API 卡片上原来那句"只带当前 aud 那个 API 的 roles 和 entitlements",改为人话。

#### 认证源

导航里叫「认证源」,排在「设置」前面:两者都在回答"用户怎么登录",但认证源是对象集合(多个实例,各有不可改字段、回调 URL、已绑定人数),设置是实例开关。

- **列表**:已添加的认证源,显示名称、类型、Provider ID、启用状态、已绑定人数;行内操作 编辑 / 停用·启用 / 删除。
- **添加**先进入选类型页,给一张类型目录,选完进入表单;编辑页就是详情页。
- **类型目录**(类型由代码注册、随二进制发布,ADR 0004):
  - **Google**、**Microsoft**、**GitHub**:常见供应商,开箱可用;端点、scope 与品牌写死在类型里,表单只问 client_id 与 client secret。
  - **通用 OIDC**:自填 issuer(必须提供 discovery)、client_id、client secret;issuer 创建后不可改。
  - **通用 OAuth2**:自填 authorization、token、userinfo 三个 endpoint、scope,以及 **userinfo 里哪个字段是用户 ID**;不校验 id_token,身份不带上游签名背书(ADR 0013)。这个字段必须选上游不会变的(如 GitHub 的数字 `id`,而不是随时可改的 `login`)。
  - **Apple**:Team ID、Key ID、`.p8` 私钥、Services ID、Bundle ID。
  - **飞书**、**Lark**、**钉钉**:企业自建 / 内部应用,只问 client_id 与 client secret,帮助文字写明谁能登录、应用里要开什么。
  - **企业微信**:企业 ID(不可改)、AgentId、Secret;帮助文字写明可信域名、企业可信 IP、可见范围,以及不要改已登录成员的账号。
- Google、Microsoft、GitHub 与两个通用类型**共用同一份实现**,差别只在端点、scope、品牌是否预填;飞书 / Lark、钉钉、企业微信各有独立实现。
- **Microsoft 比其他供应商多一个字段**:不可改的租户,填 `common`、`organizations` 或具体租户 ID;前两者接受任意 `https://login.microsoftonline.com/<租户 GUID>/v2.0` 的 issuer,其余值严格校验(ADR 0013)。
- **Provider ID** 只在添加时填,之后不可改,出现在回调 URL 与直连认证 API 里;issuer(通用 OIDC)、租户(Microsoft)、企业 ID(企业微信)同理。回调 URL 显示在表单里,可以复制。
- **停用**的确认弹窗写明"N 个用户已绑定,其中 M 个没有其他登录方式,停用后他们无法登录"。还有绑定的认证源不显示删除按钮。
- 用户详情的「已绑定的外部账号」分区列出认证源名称和绑定时间;持有 `users:write` 的管理员可以解绑,受"最后一个登录途径"约束。

#### 登录体验

三个 Tab,依次为登录方式(默认)、品牌、用户协议,`?tab=` 取值 `login` / `brand` / `terms`。宽屏右侧固定一张「预览」卡,画出托管登录页第一步,桌面 / 手机两种宽度可切;改动开关、品牌名、Logo、主色后预览立刻跟着变(未保存的值也反映在预览里),它只是示意,不发请求。切走 Tab 时未保存的输入会丢,不做离开提醒。

- **登录方式**:开放注册、密码登录、Passkey、必须绑定手机号、两步验证("管理员必须启用两步验证或 Passkey"开关)。开关**拨动即保存**,不配保存按钮:开放注册、密码登录、Passkey、必须绑定手机号归在「注册与登录」一组,管理员两步验证单独一组「管理员」,每个开关一行,说明在左、开关在右;需要确认的(打开必须绑定手机号)先弹确认框,取消就不动;保存进行中所有开关暂时禁用(`PUT /settings` 整体提交,两个开关同时保存会互相覆盖);后端拒绝时开关回到原位,原因显示在该行下方。自己既没开两步验证也没有 Passkey 时保存"打开",后端拒绝,分区内显示 Alert「请先为自己开启两步验证」。密码登录是「允许密码登录」开关,只有开与关两档;关它时若自己除密码外没有别的登录途径,后端同样拒绝。开放注册是一个开关,默认打开,关闭后的行为见 [identity.md](identity.md#不变式) 不变式 2。

Passkey 开关默认打开,关它时若自己只剩 Passkey(既没开两步验证)同样被拒绝,同一个 Alert。关闭后所有 Passkey 入口都消失(登录页、账号中心、`/.well-known/passkey-endpoints`),ceremony 一律拒绝,已添加的 Passkey 保留,重新打开即恢复可用;关闭期间 Passkey 也不再满足"管理员必须启用两步验证或 Passkey",只剩 Passkey 的管理员会被拦在管理端外。`/.well-known/` 的两个关联文件还服务密码管理器的自动填充,不受开关影响。

开关打开后,既没开两步验证也没有 Passkey 的管理员进入管理端(或已经登录着、下一次调用 API)时,整个管理端换成**拦截页**:写明「需要先开启两步验证或添加 Passkey」,按钮「去账号中心」。前端凭错误码 `two_factor_required` 识别,不靠文案。账号中心本身不受开关影响。
- **用户协议**:用户协议、隐私政策两个 URL,可选的英文用户协议和英文隐私政策两个 URL,加版本号;英文登录页优先用英文链接,没填就用中文的;中英文协议算同一版。一组输入框,按分区「保存」。它管的是合规文本,不是登录途径,所以不和登录方式的开关放在一起。
- **品牌**:实例的品牌名、Logo、主色(ADR 0028),各 Application 的托管页默认用它。Logo 选了文件就上传、当场生效,可以更换和移除;品牌名和主色随分区保存。主色有取色器和 `#rrggbb` 文本框,对比度不到 4.5:1 时字段下方提示,后端同样拒绝。
- **外部登录**:登录方式 Tab 里单独一组,列出已启用的认证源名称,给「管理认证源」链接;启停在认证源页做。

#### 验证码通道

- **通道**:短信、邮件、每日发送上限。短信、邮件各占列表一行,显示状态和未启用的后果(如"未启用时,用户无法使用手机号验证码登录");操作为「启用」或「编辑 / 发送测试 / 停用」,启用与编辑在抽屉里选供应商并填配置,发送测试用对话框;不另做空状态。
#### 安全

令牌签名密钥(列表与轮换)、审计保留期,各一张卡片。

#### 角色与权限

所有 API 资源上的角色汇总成一张表,数据来自 `GET /roles`:角色名、所属 API 资源、权限数、持有人数、是否默认(徽章)。按 API 资源筛选,搜索角色名或 key。行点击进入该 API 资源详情的角色页;添加、编辑角色仍在 API 资源详情里做,本页工具栏的「添加角色」先选 API 资源再打开同一个抽屉。内置 API 资源的角色标「内置」。

#### 协议字段(只出现在开发者组)

- **原文加一句说明**:`client_id`、client secret、Webhook;access token 只出现在说明文字里。

### 文案风格指南

1. **标题与标签**:中文名词短语,不带单位括号,单位放进输入框后缀(「Session 闲置寿命(天)」→「闲置多久需重新登录」+ 后缀「天」)。保留原文的技术字段,整个标签就用原文(`client_id`),不和中文拼成混排标题;需要时在标签旁用小字附原文(「回调地址 redirect URI」)。
2. **帮助文字**:放在字段下方,一句话说清是什么或填什么,尽量不超过 30 字。不解释动机、不安抚、不讲内部机制,不把每个边界情况都写进来;操作的后果写在确认框里。开关只写「开启后,……」。不言自明的字段(如名称)不写帮助。
3. **格式与默认值**:放进占位符或输入框后缀,不写进帮助文字。
4. **占位符**:只放示例或默认值;输入后就看不见了,所以不放必须看到的说明。
5. **错误提示**:一句,说怎么改。例:「填写通知地址时需同时设置 Webhook 密钥。」
6. **确认框**:用对话框,不用浏览器原生的 `confirm()`。标题是带对象名的问句,正文说后果(谁受影响、能否撤销),确认按钮写 动词 + 对象(「删除应用」「重新生成」),不写「确定」。删除类操作放在页面底部的红框独立区块里,先说明后果,再给按钮。
7. **语气与称呼**:管理端省略主语,或以「用户」「应用」作主语,不写「你」「本人」「对方」,也不让「认证服务」当主语做动作;账号中心面向终端用户,可以称「你」。不用口语(「进不来」「拿不到」「建出来的」)。品牌只出现在导航外壳和登录页(见[视觉规范](#视觉规范))。用全角中文标点,中英文之间留空格。
8. **分区**:分区标题按"这组设置管什么"来命名(基本信息、访问令牌、登录跳转、用户删除通知);只有一句帮助说不清"为什么"时,分区才加一句导语(如用户删除通知)。

### 视觉规范

管理端、账号中心和登录页共用一套视觉语言:中性灰打底,主色靛蓝,克制、高信息密度,接近 Linear 与 Clerk 的气质。原型(一次性)见分支 `prototype/redesign` 的方案 D(Linear 靛蓝)。本次只做浅色。它取代此前的「星云」规范。

**一体感来自一致,而不是装饰。**下面每一条都是能逐页检查的规则。

#### 配色

颜色只从下表取,写成 `styles.css` 里的 token(映射到 shadcn 的 `--primary`、`--muted` 等),页面里不写死色值。

| Token | 色值 | 用途 |
|---|---|---|
| 主色 | `#5E6AD2`,悬停 `#4E5AC0` | 主按钮、选中的开关、焦点环、进度、趋势线 |
| 主色浅底 | `#EEF0FB` | 强调块(上手清单左栏)、头像底、角色标签 |
| 主色文字 | `#4752B8` | 链接,浅底上的文字 |
| 画布 | `#FBFBFC` | 内容区底色 |
| 侧栏 | `#F4F4F6`,选中项 `#E8E8EC` | 侧栏底色;选中项灰底、黑字、图标用主色 |
| 面板 | `#FFFFFF` | 卡片、输入框、对话框 |
| 凹陷 | `#F4F4F6` | 表头、分段控件底、保存栏、代码外的标识块 |
| 正文 | `#1B1B1F` | 标题、正文 |
| 次要 | `#6B6F76` | 标签、说明、未选中的导航 |
| 弱 | `#80848B` | 时间、计数、占位(只用于辅助信息) |
| 分隔线 | `#E6E6EA`,强 `#D5D6DB` | 卡片描边、分隔线;输入框与描边按钮用强的 |

- 白字在主色上 4.7:1,主色文字在浅底上 5.8:1,都满足 WCAG AA。
- 成功、警告、危险用绿、琥珀、红,各配一个浅底,只表达状态,不作装饰。状态徽章是「圆点 + 文字」的胶囊,不只靠颜色区分。
- 每张卡片的主操作用主色实心按钮(「保存」、列表页和空状态的「创建…」「添加…」);次要操作(复制、测试发送、轮换、禁用 / 恢复)用描边或文字按钮;删除类用红色描边。

#### 外壳

- **侧栏**:宽 240px,侧栏色底,右侧 1px 分隔线。顶部是 Polaris 标志(主色方块里的四角星)和「Polaris」,中间是[导航](#导航)的分区,底部是当前管理员(头像、主标识、角色),点开是「账号中心」「退出登录」菜单。导航项高 34px,图标 16px 在左,计数在右。
- **顶栏**:高 56px,贴顶,半透明画布色加模糊,底部 1px 分隔线;内容见[导航](#导航)。面包屑在顶栏里,不再占内容区:一级页面只显示自己的名字,详情页显示「分区 / 分组 / 对象名」,最后一级加粗、不可点。由路由的 `staticData.crumb` 给出。
- **内容区**:左右 32px、上 28px 内边距(窄屏 16px),最宽 1320px,靠左。

#### 页头与卡片

- **页头**:标题 22px 半粗,下一行一句次要色说明(列表页写数量,如「1,284 个用户,其中 23 个待激活」);操作按钮靠右。详情页标题左侧是 48px 的对象图标块(主色浅底),标题后接类型徽章;下一行是**标识条**:每项为「名称 + 等宽值 + 复制图标」的小块,点击即复制。再往下依次是页面特有的提示(接入清单、警告)和 Tab 栏。
- **卡片**:分区一律放进卡片:白底,1px 分隔线描边,圆角 8px,极淡阴影。卡片标题行 14px 半粗,下面 1px 分隔线,右侧放作用于整张卡片的操作(「全部下线」「轮换签名密钥」)或「查看全部」链接。卡片之间 16px。卡片里不再套卡片。
- **表单卡片**:字段最宽 560px;卡片底部是凹陷色的保存栏,右对齐「撤销修改」+「保存」,有改动才可点。
- **开关行**:说明在左(标题 + 一行次要色说明,标题前可放图标),开关在右,行间分隔线;依赖警告放在说明下方。
- **属性行**:只读的值用「名称 / 值」两列(名称 96–144px 固定列),不用禁用的输入框。
- **详情侧栏**:应用详情等开发者页面,宽屏右侧有 360px 的辅助卡片(「接入指南」:Issuer、`client_id`、回调地址和按语言切换的代码片段);窄屏移到主内容下方。
- **表格**:表头凹陷色底、12px 次要色;行高约 52px,悬停浅主色底,整行可点进详情;第一列是对象(头像或图标 + 主标识 + 次要信息),操作收进行尾的「…」菜单。工具栏在表格卡片顶部:搜索框、分段控件、虚线「+ 筛选」按钮;底部是分页(「第 1–20 条,共 N 条」+ 上一页 / 下一页)。
- **统计卡**:四张一行(窄屏两张),图标 + 标签、28px 半粗等宽数字、一行变化或说明、可选的趋势线。
- 只有三种块可以有底色或特殊边框:**强调块**(上手清单左栏、告警条)用浅底、无边框;**危险区**用红色描边的独立块,放在页面最下方;**空状态**用虚线框。
- 不用 emoji、渐变和插画。图标只用 lucide,线宽 1.75。例外:登录页上具名供应商(Apple、Google、Microsoft、GitHub、飞书 / Lark、钉钉、企业微信)的按钮按各自的品牌规范用官方标志和规定样式;通用 OIDC、通用 OAuth2 的按钮仍是纯文字。

#### 尺寸

- **圆角**:卡片、对话框、登录卡 8–12px,按钮、输入框、导航项 6px,头像、状态点、徽章为圆形或胶囊。
- **间距**:只用 4 / 8 / 12 / 16 / 24 / 32 px 这几档。
- **字号**:页面标题 22px 半粗;卡片标题 14px 半粗;正文 14px;标签、辅助文字 13px;表头、时间、计数、徽章 12px;统计数字 28px 半粗,等宽数字。字体为 Inter 加系统中文字体,等宽为 JetBrains Mono。
- **控件高度**:按钮、输入框 34–36px,小号按钮 28px,登录页 40px。

#### 动效

- 状态变化用短过渡,不让元素瞬变:按钮、导航项、行悬停 100–150ms,输入框描边与焦点光晕 150ms,开关滑块 150ms。过渡只覆盖颜色、阴影和位移,不改宽高。
- 抽屉从右侧滑入,对话框淡入;页面进场不做动画。持续转动的只有加载指示。
- 尊重 `prefers-reduced-motion`:去掉过渡,加载指示保留。
- 表单提交后按钮进入等待态(转圈),慢网络和 PoW 求解都有反馈;`altcha-widget` 自带进度,不再叠加。六位验证码填满即自动提交。

#### 登录页

登录、绑定、协议同意、首次引导、退出登录、**邀请接受页**(`/invite`,设完密码当场登录,再回到 Application 就不用登了)等页面(`internal/login/pages.html`)用同一套 token。

- 浅灰画布上居中一张白色卡片,宽 400px,圆角 12px,1px 分隔线描边加柔和阴影;窄屏卡片占满宽度(左右 16px)。
- 卡片上方是品牌行:品牌标志和品牌名,下一行是口号「一个账号,登录 <品牌名> 的所有应用」(英文页「One account for every <品牌名> app」)。
- 卡片以 Application 为主角:顶部是生效品牌的 Logo(没设就是 Polaris 标志),标题「登录」,下一行「继续前往 <Application 名>」;外部登录与 Passkey 按钮在「或」分隔线下方;卡片底部是「由 Polaris 提供安全登录」。
- **品牌**(ADR 0028):托管页能定制的只有品牌名、Logo、主色三项,实例设默认,Application 逐项覆盖。能认出 Application 的页面用它的生效品牌;认不出的(邀请接受页、首次引导、不带 `id_token_hint` 或 `client_id` 的退出页、授权请求本身无效时的错误页)用实例品牌。
  - 一项都没设时,品牌行是 Polaris 标志和「Polaris」,主色是靛蓝。
  - 设了任何一项:品牌行和卡片顶部换成 Logo(没设就不放)和品牌名(没设就写 Polaris);卡片底部的「由 Polaris 提供安全登录」隐藏。退出页的「退出 …？」也用品牌名。
  - 品牌名替换品牌行、口号里的「Polaris」和 `<title>`;表单区的「继续前往 <Application 名>」不变。Logo 同时用作 favicon,由 Polaris 自己在 `/brand-logos/{key}` 提供(带 `Content-Security-Policy: sandbox`),托管页只用 `<img>` 引用。
  - 主色只配一个 `#rrggbb`,服务端推出 `--primary`、`--primary-hover`(加深)、`--primary-soft`(浅底)、`--primary-ink`(加深到在浅底上达到 4.5:1)四个值写进页面;保存时要求白字在主色上达到 WCAG AA 的 4.5:1。
  - 不开放自定义 CSS、HTML 模板、主题或 JS。要整页自己设计登录界面的 Application,用直连认证 API 自己画 UI。
- **先输标识**:任何时候页面上只有一套表单。
  1. 第一步只有一个标识输入框、协议勾选和「继续」,下面是「使用密码登录」链接。
  2. 手机号或邮箱:「继续」时才运行 PoW,发码后进入填码页。用户名:不发码、不运行 PoW,直接进入密码步骤。
  3. 填码页和密码步骤顶部显示标识和「更换账号」(回到第一步);协议勾选只在第一步出现,之后用隐藏字段带上。填码页的「重新获取」直接向同一个标识重发,不再做人机验证;距上次发送不足 60 秒时按钮不可点,与按标识符的发送限制一致。
  4. 「使用密码登录」切到「标识 + 密码 + 协议勾选」的表单,其中有「改用验证码登录」。
  5. 密码登录设为关闭时不显示「使用密码登录」,输入用户名提示「该账号不能用验证码登录」,不透露账号是否存在。
  6. 只有一种方式可用时直接显示那一种:没有通道就只有密码表单。
  7. **邀请接受页是特例**:它是从邮件点进来的,没有 Application 可指,所以标题就是「设置密码」,只说明"设置密码后即可使用账号",一个密码框加一个「设置并继续」。设完密码只在没有别的步骤剩下时才当场登录(见 authentication.md 的注册邀请);链接不好用(过期 / 用过 / 已撤销)时给一句人话并指向管理员,不复用发码失败那套文案。
- 所有密码框右侧带「显示」切换,点开后改为「隐藏」;只改输入框的可见性,不动输入内容、autocomplete 和校验。
- **多语言**(ADR 0028):托管页只有 `zh-CN` 和 `en` 两种语言。选择顺序是 OIDC `ui_locales` > `Accept-Language` > `zh-CN`,各取第一个支持的;`zh*` 一律归为中文(含 `zh-TW`),`en*` 归为英文,其他语言退回中文。`ui_locales` 随这次登录保存,之后的填码页、密码步骤、两步验证等都沿用;退出页读退出请求的 `ui_locales`。文案(含 Go 代码里产生、显示在页面上的错误提示)来自内嵌的消息表(`internal/login/messages_en.go`,以中文原文为 key),`<html lang>` 跟着语言变;管理员不能覆盖文案,页面上不放语言切换器。Application 名原样显示,不分语言。

### 创建应用与接入清单

原型见 [`prototype/app-create`](https://github.com/zibyn/polaris/blob/prototype/app-create/prototypes/app-create/index.html):创建页取 A 版,接入清单取 C 版。

**创建**

1. 在「应用」列表点「创建应用」,打开右侧抽屉,先选平台:给五张平台卡片,卡片下注明对应的类型:

   | 卡片 | 类型 | 回调地址 |
   |---|---|---|
   | 手机 App | 无后端应用(public) | 不需要(走直连认证 API) |
   | 小程序 | 无后端应用(public) | 不需要(走直连认证 API) |
   | 纯前端网页 | 无后端应用(public) | 必填 |
   | 有后端的网站 | 有后端应用(confidential) | 必填 |
   | 后端服务(M2M) | 后端服务(m2m) | 不需要 |

2. 第二步只填**名称**,网页类再加**回调地址**(必填),后端服务再选**默认 API 资源**(必填)。抽屉标题下注明类型和"创建后不能更改",可以返回换平台。
3. 其余字段(退出后跳转地址、闲置多久需重新登录、允许 App 保持登录、用户删除通知)创建时都不问,留到应用详情里填。
4. 平台只用于引导,不入库;创建请求仍是 `{type, settings}`,Management API 不改。

**接入清单**

创建成功后直接进入应用详情,顶部显示「接入清单」,可以收起。清单由创建跳转时 URL 带的平台参数(如 `?onboarding=spa`)渲染,只显示这一次;之后从列表再进详情就不显示了。各项根据应用数据自动打勾:

1. 记下 `client_id`(自动完成,带复制按钮)。
2. 保存 client secret(无后端应用以外的都有):只显示这一次,勾选「我已保存」之前不能离开页面。
3. 选择默认 API 资源(可以跳过;帮助文字说明不调用自己的 API 就可以不选。后端服务的默认 API 创建时就选定了,这一步自动完成)。
4. 接入代码,按平台给出片段:手机 App 用 KMP SDK;小程序指向直连认证 API 文档;纯前端网页用 oidc-client-ts;有后端的网站用后端语言的 OIDC 库(issuer、`client_id`、client secret);后端服务用 `client_credentials` 换令牌的示例。另外列出认证服务地址。

清单末尾有两句提示,链到别处:去登录体验的「登录方式」检查登录方式;需要在用户注销时清理数据,就配置「用户删除通知」。

### 审计

**行**:三列,依次为 时间、操作人、事件描述。事件描述是一句话,句中的对象可以点击(用户 → 用户详情,应用 → 应用详情),例如「禁用了用户 138****0001」「把用户 a@x.com 在 订单 API 上的角色设为 编辑、只读」。概览页的「最近事件」用同样的一句话,排成分隔线列表(见[视觉规范](#视觉规范))。

**操作人**:显示主登录标识,数据来自 `GET /audit` 的 `user` / `byUser` 字段。缺省规则如下:

- 没有 `by` → 「系统」;但只有账号本人才能做到的事件(`login.succeeded`、`invite.accepted`、`recovery_code.used`)没有 `by` 时显示「用户本人」;
- `detail.byType` 为 `application` → 应用名称(数据来自 `/applications`);应用已删除或读者没有 `applications:read` → 等宽的原 client_id;没有 `byType` 的老记录按 User 解析;
- `by` 等于 `sub` → 「用户本人」;
- 用户已删除 → 「已删除的用户」加 ID 前 8 位(等宽字体)。

**详情字段**:

- `clientId`、API 资源标识符、角色 key:前端用 `/applications`、`/apis` 映射成名称;对象已删除,或读者没有 `applications:read` 时,退回等宽的原 ID。

- `kind` 映射为 手机号 / 邮箱 / 用户名;`limit` 写进句子(「每日上限 N 条」);`ip` 原样写进句子。
- `session`(会话 ID)不显示;Webhook 的 `id`(投递 ID)只放在悬浮提示里。
- Provider ID(`id`、`provider`)显示为等宽的原 ID;吊销失败的 `error` 只放在悬浮提示里。
- `settings.updated` 不记录改了什么,句子只写「修改了登录设置」。

### 空状态

- 管理员本身就是用户(ADR 0006),所以用户列表、会话、审计总有数据,不存在真正的空。
- **应用、API 资源列表"只剩内置项"就算空**:列表上方放引导块,内置项照常列出,标「内置」。出现第一个非内置对象时引导块消失,不能手动关闭。
- **三种引导各管一件事**:概览上手清单管跨页面的先后顺序;接入清单只管刚创建的那一个应用怎么接上;空状态只讲本页对象是什么、为什么需要,给一个入口,不复述步骤。缺少前置条件的,归[依赖提示](#依赖提示)。
- **格式**:标题加一句说明加主按钮(动词 + 对象),不配插画,不解释概念。只读角色看不到按钮时,写一句"需要「…」角色才能创建"。
- **筛选 / 搜索无结果**和真正为空分开写:"没有符合条件的…"加「清除筛选」,不放创建入口。适用于用户列表、审计、角色筛选。

| 位置 | 触发 | 标题 | 说明 | 按钮 |
|---|---|---|---|---|
| 应用列表 | 只剩内置 | 还没有应用 | App、网站或小程序需先在此创建,用户才能登录。 | 创建应用 |
| API 资源列表 | 只剩内置 | 还没有自定义 API 资源 | 后端需要权限控制时添加。仅使用登录可不添加。 | 添加 API 资源 |
| 认证源列表 | 0 条 | 还没有认证源 | 添加后,用户可使用 Google、GitHub 等账号登录。 | 添加认证源 |
| API 资源详情・权限 | 0 条 | 还没有权限 | 先定义权限,再组合成角色。 | 添加权限 |
| API 资源详情・角色 | 0 条 | 还没有角色 | 将权限组合成角色,再分配给用户。 | 添加角色 |
| 用户列表 | 只有管理员 | 还没有管理员以外的用户(一条都没有时为「还没有用户」) | 用户注册或由管理员创建后显示在这里。 | 创建用户 |
| 用户详情・角色 | 0 条 | 没有角色 | 用户当前没有任何权限。 | 分配角色 |
| 用户详情・会话 | 0 条 | 没有登录中的设备 | 该用户当前未在任何设备上登录。 | 无 |
| 用户详情・Passkey | 0 条 | 没有 Passkey | 这个用户还没有添加过 Passkey。 | 无 |
| 概览・最近事件 | 0 条 | 最近没有事件 | 超过审计保留期的记录已经删除。 | 无 |

- 用户详情的角色区:没有可分配的角色(只剩管理 API 的内置角色)时,在按钮旁链到「API 资源」去建角色。
- **用户列表"只有管理员"就算空**,做法同应用列表:引导块在上,管理员照常列在下面。管理员本身就是用户,概览也把他们计进用户数,列表把他们藏起来会和概览对不上。
- **"只有管理员"的判断**:不加筛选(搜索、角色、状态都不设)的 `GET /users` 第一页 `hasMore` 为 false,并且每个用户的 `roles` 都含管理 API 上的角色。一条都没有也算。

## 账号中心:单页长滚动

原型(一次性)见分支 `prototype/redesign` 方案 D 的「账号中心」。

面向 User,桌面和手机共用一个页面,外观按[视觉规范](#视觉规范):顶部白色品牌栏(品牌标志、品牌名,右侧返回链接和头像);下面最宽 1040px 居中,宽屏左侧 220px 是锚点目录(个人资料、登录方式、安全、设备、最近登录、数据与隐私),随滚动高亮当前分区,点击跳到锚点;窄屏目录收成顶部横向一排。每个分区是一张卡片。从上到下依次是:

1. **头部**:头像、姓名和主标识、加入时间,右侧「编辑资料」。下方一行**账号安全**:圆环显示已满足几项(已验证的手机号或邮箱、两步验证、Passkey;实例关掉 Passkey 时不计它),写「良好」或「待加强」,并针对第一项未满足的给一个主按钮(如「开启两步验证」)。顶部品牌行用实例品牌;以 `/account?client_id=<id>` 打开时用该 Application 的品牌,它填了首页地址时右侧多一个「返回 <Application 名>」链接,只链登记的首页地址,不收任意返回地址(ADR 0034)。未知的 `client_id` 按没带处理。管理员(持有 Management API 的 Role,`GET /v1/account/me` 的 `admin`)在顶部品牌行右侧多一个「返回管理端」链接:管理端菜单能进账号中心,这里也要能回去。
2. **登录方式**:手机号、邮箱(更换、解绑)、外部身份(解除绑定;"绑定其他账号"只列出管理员启用的 Provider)。每项一行:图标块、名称与当前值、状态徽章(已验证 / 未开启)、操作按钮。
3. **安全**:密码(开关允许时显示)、Passkey(实例开关允许时显示)、两步验证(开关与恢复码)。
4. **设备与会话**:每个 Session 的设备、IP、最近活动,可以下线;也可以一次下线其他设备(本设备保留);已结束的 Session 显示 30 天。
5. **最近登录**:本人 30 天内的登录成功、失败和密码锁定(取自审计日志的 `login.succeeded`、`login.failed`、`login.password_locked`),倒序混排,最多 50 条,不分页,查看不要求重新认证。每行显示时间、结果、方式、Application(取不到名称时退回 `client_id`)、设备和 IP;成功的方式是第一因素,经过两步验证的追加「+ 两步验证」,失败的方式是出错的那一步(如「密码错误」),锁定显示锁到什么时候。30 天内有失败时顶部写「过去 30 天有 N 次登录失败」,N 不受 50 条上限影响、不含锁定;底部提示修改密码并下线其他设备,不提供逐行操作。
6. **数据与隐私**:导出我的数据(JSON)。
7. **危险操作**:注销账号(重新认证,并输入"注销"确认)。

安全分区的 Passkey:每把显示名称(默认按提供方命名,如"1Password";查不到叫"Passkey")、创建时间和最后使用时间,可重命名(不要求重新认证)和删除(要求)。添加和删除都要求近期重新认证,都写审计;浏览器不支持 WebAuthn 时分区仍在,只是没有「添加」按钮。实例的 Passkey 开关关闭时整个分区(含重新认证时选 Passkey 的路子)都不出现,已添加的 Passkey 保留,重新打开即回到列表。`/.well-known/passkey-endpoints` 把密码管理器指到这里的锚点(`#passkeys`)。

所有敏感操作都在弹窗里先完成近期重新认证,规则见 [identity.md](identity.md#换绑与解绑)。
