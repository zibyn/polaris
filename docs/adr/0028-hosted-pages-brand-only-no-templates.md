# 托管页只开放品牌，不开放模板、HTML 和 JS;完整定制走直连 API

托管页能定制的只有品牌：品牌名、Logo、主色。实例设一套默认,Application 可以逐项覆盖。文案来自内嵌在二进制里的中英两张消息表，管理员不能改。要完全自己设计登录界面的 Application,用直连认证 API(ADR 0002、0010)自己画 UI。理由是登录页经手密码和验证码，任何能注入 HTML 或 JS 的定制都会成为 XSS 和凭据窃取的入口。而且模板一旦开放，页面结构就成了对外契约，以后每次改登录流程都会弄坏别人的模板。直连 API 已经覆盖了「完全自建」这一档，所以中间几档的收益不大。调研见 `docs/research/login-customization.md`。(#152)

## Considered Options

- **自定义 CSS**(Logto):不能执行脚本，但类名和 DOM 结构会变成事实上的契约。等真有人需要时再加，只开放 CSS,并配严格的 CSP。
- **HTML 模板加表单插槽**(Auth0 的 Liquid 模板):允许 JS,Auth0 自己也说类名和结构会变。
- **整页替换主题**(Keycloak、Casdoor):恶意模板能以服务进程的身份执行代码，升级时每套主题都得跟着改。

## Consequences

- 登录页改版只需要保证品牌三项和消息表的 key 不变，不必顾及第三方模板。
- 单条文案覆盖(按语言加 key)以后可以在消息表上加，不违背本决定。
- 托管页以后可以收紧 CSP(`script-src` 和 `img-src` 都只允许 `'self'`),没有第三方模板挡路。Logo 由 Polaris 自己提供，不引用外链。
